Signing baselines

Both signing series sign the same deterministic message set; they differ only in what is put on the wire and what has to be signed.

  • MTL amortised (condensed signature + one signed ladder) — one signed Merkle tree ladder is shared across the whole batch and every message carries only a condensed authentication path. Wire bytes = ladder + Σ condensedi.
  • No amortisation (full MTL signature on every message) — every message carries a complete MTL signature: its condensed path concatenated with the ladder. Wire bytes = Σ condensedi + N × ladder.

"No amortisation" is the MTL wrapper's non-amortised mode, not a plain SLH-DSA RRSIG (which would carry a single full SLH-DSA signature per RRset and no ladder). The wire-byte formulas for each configuration are documented in docs/BASELINES.md.

Percentages are shares of that row’s messages; “max response” is the largest length carrying at least one modelled message. TCP fallback is modelled as 3 round trips with the TCP payload adding 4 bytes of length framing to the response. Fallback delay is omitted: no RTT was supplied to the consolidator, so no delay was modelled.

Methodology & scope

Timings are Criterion-measured means with 95% confidence intervals. Hollow bars and fitted curves are extrapolations (N × mean per-message cost, or an OLS fit of the MTL-amortised batch total) — descriptive summaries of the measured runs, not measurements themselves; every chart carries a three-line footnote naming its source files. Wire-size and memory figures are exact measurements of real output.

This report presents empirical benchmark measurements only. No formal security guarantees or proofs are claimed.
