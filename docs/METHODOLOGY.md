# Methodology

How CLIMB measures, what each number's evidence class means, and where the
numbers come from. The three dataset sizes are Small (100 messages), OneK
(1,000), Medium (10,000) and Large (1,000,000); the algorithm throughout is
SLH-DSA-SHA2-128s-MTL-SHA2-128, the small-signature variant chosen because
DNS-over-UDP is exactly the size-sensitive context MTL mode targets.

## Environment pinning

Every measurement run records its environment before measuring:

- `rust-toolchain.toml` pins the exact Rust toolchain and `Cargo.lock` is
  committed, so the workspace builds from the same crates on every machine.
- `third_party/liboqs` and `third_party/MTL` are git submodules pinned to
  exact commits; OpenSSL and liboqs are built inside Docker from pinned
  sources (`docker/Dockerfile.build`), so the native stack a benchmark links
  against is reproducible independently of what the host has installed.
- `cargo xtask pin-env` writes `environment.json`: CPU model, core count,
  governor, kernel, toolchain versions, submodule commits and the recording
  timestamp.
- `scripts/pin-perf-governor.sh` fixes the CPU governor and pins benchmark
  processes to one logical CPU with `taskset`, removing two common sources of
  run-to-run variance.

Residual thermal variance on the laptop-class reference machine was observed
even under a fixed governor and pinning; it is documented as a limit rather
than averaged away.

## Determinism and seeds

Synthetic datasets are generated by `climb-dns` from a seeded ChaCha RNG with
no OS entropy: the same size and seed always produce the byte-identical
message set, on any machine. Each measurement artifact records the seed its
dataset was generated from (the wire, memory and ladder artifacts all carry
their `distinct_seed`), so a re-run can prove it signed the same bytes, and
the TUI Method tab lists the seed of every artifact the results were built
from. Determinism ends where measurement begins: timings still vary with the
machine, which is why trials are repeated and distributions are reported.

Dataset determinism is itself recorded as evidence in
`docs/sample-output/dataset-digests.json`: one SHA-256 per dataset size over a
domain-separated, length-prefixed encoding of the generated messages. The
routine validation run recomputes Small, OneK and Medium; the million-message
entry is left to an explicit deep check. A document that is present but
unreadable is an error naming its path, not a silent skip.

## Sampling and extrapolation

Signing and verifying times come from Criterion benchmark groups: warmup,
repeated samples, outlier treatment and confidence intervals built in. Each
condition (dataset size × configuration × metric) is its own group, and the
CLI-level and FFI-level timings are kept distinct where both exist.

Two honest constraints shape the matrix:

- The non-amortised conditions cost one full signature per message, so the
  largest sizes cannot be measured end to end in feasible wall-clock time
  (the slowest groups would run for weeks). Those batch costs are
  **extrapolated**: the measured per-message cost times the message count,
  rendered with `≈` and classed `EXTRAPOLATED` everywhere they appear. The
  linear-scaling identity was validated against an intermediate measured
  dataset size before being applied to the unmeasured ones.
- Transmitted bytes need no extrapolation at all: they are measured exactly,
  per size, by signing the full deterministic dataset and summing the wire
  output of each configuration.

## Wire sizes: three descriptions that must agree

Every wire number has an exact, non-cryptographic definition. With `h = 16`
bytes per hash and `i = 8` bytes per serialized `MTL_INDEX`:

- **condensed signature** — `3h + 2 + 3i + 2 + k*h` = `3h + 28 + k*h`, where
  `k` is the number of sibling hashes on that leaf's authentication path;
- **unsigned ladder** — `2 + 2h + 2 + c*(2i + h)` for `c` rungs, where `c` is
  the population count of the leaf count and each rung covers one set bit;
- **signed ladder** — the unsigned ladder plus a 4-byte big-endian signature
  length plus the underlying signature.

The field order these lengths count is the one in
`third_party/MTL/src/mtl_buffer.c`. Three descriptions are kept independent and
required to agree: the literal arithmetic above, the named model functions in
`climb-analytical`, and real libMTL output parsed field by field. The agreement
sweep covers every leaf count from 1 to 64 and the sizes 100, 1,000, 10,000 and
1,000,000; any disagreement fails the test rather than being rounded into a
table.

Two accounting facts matter when reading the comparison. A complete MTL
signature (`condensed || ladder`) is larger than a plain SLH-DSA signature at
small batches, because the ladder itself carries an SLH-DSA signature;
amortisation only wins once that ladder is shared over enough messages. And the
difference between the non-amortised and amortised totals is exactly
`(N - 1) × ladder` bytes — the only bytes saved are the repeated ladders. The
byte-accounting test sums the reconstructed buffers themselves instead of
trusting either formula.

## Structural validation of untrusted MTL bytes

The native verifier's bounds checks are permissive in two places: it accepts
bytes appended after a signed ladder, and it does not compare the declared
signature length with the signature it actually reads. The safe wrapper
validates the pinned layout before calling native code, so malformed input is
reported as a typed error rather than coerced or silently truncated:

| Input | Outcome |
| --- | --- |
| Empty message, or one longer than 65,535 bytes | `EmptyMessage` / `MessageTooLong` |
| Condensed buffer shorter than the fixed prefix | `MalformedCondensedSignature` |
| Foreign series id in a condensed signature or ladder | `MalformedCondensedSignature` / `MalformedLadder` |
| Non-zero flags field | `MalformedCondensedSignature` / `MalformedLadder` |
| Sibling count or rung count inconsistent with the buffer length | `MalformedCondensedSignature` / `MalformedLadder` |
| Declared signature length different from the scheme's | `MalformedLadder` |
| Bytes appended after a complete structure | `MalformedCondensedSignature` / `MalformedLadder` |
| Bit flip inside a well-formed structure | `Ok(false)` |
| Signature from a different keypair | `Malformed*` or `Ok(false)` |
| Empty batch, or an empty message inside a batch | `EmptyBatch` / `EmptyMessage` |

The distinction is deliberate: a layout error says the peer sent something that
is not a serialized MTL structure, while `Ok(false)` says the structure was well
formed but did not authenticate. A bit flip is therefore always a cryptographic
rejection, never a parse error.

## Memory: measured and analytical, kept separate

The measured quantity is the process resident set of a fresh, isolated
process: the probe spawns one process per sample, generates the dataset,
signs, and records min / median / max / IQR over several samples, so
allocator residue from earlier work can never contaminate a reading.

The analytical quantity is computed from libMTL's own documented page model —
tree page size 1,048,576 B, up to 8,192 pages, 16 B hashes — plus the
harness's own itemised buffers (dataset vectors, ladder and condensed
buffers, keypair context). Measured and analytical are reported side by side
with the residual stated, never forced to agree; the ratio row in the headline
table is the honest summary of the model's accuracy.

## Evidence classes

Every number in the report, charts, TUI and README carries one of these
classes (the same definitions appear on the quote sheet and the TUI Method
tab):

| Class | Meaning |
| --- | --- |
| `MEASURED` | Read directly from a measurement artifact |
| `DERIVED` | Computed from other recorded values (ratios, byte arithmetic) |
| `ANALYTICAL` | Produced by a closed-form model, not measured |
| `EXTRAPOLATED` | Measured per-message cost times the message count; always rendered with `≈` |
| `UNCLASSIFIED` | Carries no recorded class (only the repository commit row) |

No number anywhere in the project is typed into source: charts, tables, the
TUI and the quote sheet all read the consolidated artifact, and
`cargo xtask deck-facts` regenerates the quote sheet from the artifacts
themselves, failing if two artifacts disagree about the same value.

## Baselines

Three configurations are compared, labelled A, B and C throughout: plain
SLH-DSA (A), MTL without amortisation (B) and MTL amortised (C). The wire-byte
formulas, the signing-benchmark realisation of each setting and the reasoning
behind the comparison live in [`BASELINES.md`](BASELINES.md); this document
does not repeat them, so there is only one place to keep correct.

## Scope

CLIMB reports empirical measurements under the pinned environment described
above. It is not a security proof, a formal verification or a certification of
MTL mode, SLH-DSA or any component, and nothing in the artifacts should be
read as one.
