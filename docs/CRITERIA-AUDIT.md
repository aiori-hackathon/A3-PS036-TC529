# PS-036 criteria audit

This audit answers one question per problem-statement item: what tracked
evidence exists, what command proves it, and what the command actually printed.
The status column is a judgement made here and mirrored in
[`COMPLIANCE.md`](COMPLIANCE.md); `cargo xtask criteria-card` reads these rows
and renders the printable judge card, so a status is never typed into the card.

Printable version: [`CRITERIA-CARD.html`](CRITERIA-CARD.html), regenerated by
`cargo xtask criteria-card`; `--check` fails when it drifts from this table.

Status vocabulary: **PASS** — the evidence exists and the proving command ran
green; **PARTIAL** — evidence exists but a named piece cannot be proved from
the repository; **FAIL** — the evidence is absent or the command failed;
**N/A** — the stated condition did not arise. In `COMPLIANCE.md` the same rows
use its narrower vocabulary (`met` = PASS, `partial` = PARTIAL, `pending` =
FAIL); no row is marked met while carrying a gap.

Commands were run on 2026-11-17 against the committed sample artifacts in
`docs/sample-output/`. They read artifacts and source; they do not re-measure.
The output excerpt is the first line or two of the real output, abbreviated
with `…` only where noted.

unmatched value. The full generated punch list is in

## What was not run

- `cargo xtask dns-demo`, `dns-cache` and `dns-rtt` are Docker-only local
  pipelines. This audit read their recorded artifacts and configuration
  instead; no container was started. The live deployment is likewise not
  probed from here.
- The deck PDF was not edited. The three stale numbers above are a punch list
  for a human, not a generated change.
- Poppler's `pdftotext` was unavailable (no `pdftotext`, `mutool`, `qpdf` or
  `gs` on `PATH`); the extraction used `pypdf` in a gitignored `target/`
  environment and the same layout mode.
- No benchmark was re-measured in this phase, by design: the audit reads the
  committed artifacts and changes no measurement code, schema or number.
