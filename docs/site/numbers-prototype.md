## Class reconciliation: "Extrapolated" versus "DERIVED"

The prototype labels the Medium signing speed-up and the Medium verifying speed-up
`Extrapolated ≈` (lines 239, 240, 305, 306, and `EV.x` at line 304). `README.md:106–107` labels
the same two rows `DERIVED`, and `docs/deck-facts.md:92,151` agrees.

The artifacts settle it:

```
comparisons[2] size=Medium class=derived sign=9434.44263867255 ver_cached=77.33947336502698
```

`target/climb-results.json` and `docs/sample-output/climb-results.json` both carry
`"class": "derived"` on the Medium comparison. `docs/deck-facts.md` states the rule: `DERIVED`
is "computed from other recorded values (ratios, byte arithmetic)" while `EXTRAPOLATED` is the
`N × per-message` identity "applied to a measured per-message cost rather than a measurement over
the whole batch" (`docs/deck-facts.md:8–13`). The speed-up is the ratio of the recorded plain
per-message cost to the recorded MTL per-message cost; `crates/climb-report/src/results.rs:1853`
computes it as `ratio(p.signing_mean_ns, c_sign.value)`. The comparison is marked `Extrapolated`
only when one of its inputs is extrapolated or missing (`results.rs:1844–1848`), and the Medium
plain figure is `MEASURED`, so the comparison is `DERIVED`.

The value that *is* extrapolated in this story is the plain A Medium batch total,
`≈1.41 h` (`k = 1`, `docs/deck-facts.md:85`), because no whole-batch plain run was performed.
The recorded comparison nevertheless classifies the resulting speed-up `DERIVED`, and the README
publishes it without `≈`.

**Correct class for both replaced rows: `DERIVED`, rendered without `≈`.** The copy deck uses
`F-sign-medium-c-vs-a` → `9,434 ×` and `F-verify-medium-c-vs-a` → `77.34 ×`.

## What could not be verified

- Values were read from artifacts, not re-measured. The audit did not run `cargo xtask bench-all`,
  `wire-report`, `memory-report` or `dns-demo`.
- The prototype numbers were confirmed stale against the current artifacts. Their provenance is
  partly recoverable: `215.3 ×` matches the superseded historical value recorded in the project
  progress log's numbers-of-record (`≈215.3 ×`, later replaced), and `9,405 ×` is close to the
  superseded `≈9,469 ×` but not equal to it, so it probably comes from a different artifact
  revision. The audit still cannot say which revision the prototype was built against; no
  provenance file for the prototype was supplied.
- Browser rendering of `data-n`/`data-d` counter formatting (`toLocaleString('en', …)`) was not
  executed; formatting claims are static reads of line 341.
