# Skin plan

How the prototype becomes the site. This is the work order for MS1–MS4, not a
description of what exists: in MS0 no file under `site/` changed.

Source of truth: `docs/site/prototype/climb-site.html` (429 lines, SHA-256
`0b0822338e004daba100bde1f98bcd9f2e5aa4c1f7b08198973d966a9570f108`).
Design constraints: `docs/site/design-rules.md`. Tokens: `docs/site/brand.md`.
Effects: `docs/site/animation-inventory.md`. Missing numbers:
`docs/site/fact-gaps.md`. Words: `docs/site/copy.md`.

## 5. Fonts plan

The prototype requests one Google Fonts stylesheet (line 7) and uses two
families: **Bricolage Grotesque** for display (`--fd`) and **Geist** for body,
UI and diagrams. The site self-hosts both; no third-party request at load time.

Fetch the stylesheet with a browser user agent so Google returns `woff2`
instead of `ttf` (an unknown agent is served `truetype`, which is four times the
bytes):

```sh
UA='Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/140.0.0.0 Safari/537.36'
curl -sS -A "$UA" \
  'https://fonts.googleapis.com/css2?family=Bricolage+Grotesque:opsz,wght@12..96,600;12..96,700&family=Geist:wght@400;500;600&display=swap' \
  -o /tmp/climb-fonts.css
grep -o 'https://fonts.gstatic.com/[^)]*' /tmp/climb-fonts.css | sort -u
```

The request above is the prototype's own URL, character for character, so the
`opsz` axis and the three Geist weights are the ones the design was drawn with.
The fetch was exercised in MS0: without the browser agent the stylesheet
resolves to `…/bricolagegrotesque/v9/…ttf` and `…/geist/v5/…ttf` URLs, so the
agent is required, and the URLs must be treated as build inputs, not copied into
the repository.

Plan:

1. Two **variable** faces, one file each: Bricolage Grotesque with the `opsz`
   and `wght` axes (one file covers 600 and 700), Geist with `wght` (one file
   covers 400, 500 and 600). Latin subset only, `woff2`, instanced to the axis
   ranges the design uses (Bricolage `opsz 12..96`, `wght 600..700`; Geist
   `wght 400..600`), `font-display: swap`.
2. No mono webfont: the prototype's mono is `ui-monospace,Menlo,monospace`
   (line 24), a system stack. The previous `geist-mono` file is removed.
3. Budget: **80 KiB** for the two files together. A latin-only variable subset
   of each is expected around 30–40 KiB; the phase records the real bytes and
   fails the budget test above 81,920 bytes.
4. Licences: both are **SIL Open Font License 1.1**, verified in MS0 from the
   upstream texts (`vercel/geist-font`, `LICENSE.txt`, "Copyright (c) 2023
   Vercel, in collaboration with basement.studio"; `ateliertriay/bricolage`,
   `OFL.txt`, "Copyright 2022 The Bricolage Grotesque Project Authors"). The
   licence files ship under `site/public/fonts/licences/` and the copyright
   line is repeated in the subsetting script's header.
5. Fallbacks: a metric-compatible system face with `size-adjust` measured from
   the new files, as the previous plan did for Instrument Serif and Geist. The
   numbers are produced by `site/scripts/build-fonts.py`, not typed.
6. Subsetting uses the existing `site/scripts/build-fonts.py` pipeline
   (`pyftsubset`, already a build dependency). No new dependency.
7. Inline `@font-face` data URIs are forbidden: they are large, uncacheable and
   make the CSS exceed the inline budget. Files only.

## 6. CSP changes

What the prototype does today and what the port must do:

| Item | Now | Target |
| --- | --- | --- |
| Inline `<script>` | the prototype has one 90-line inline script plus one 4-line script (lines 298–429) | none; every behaviour is a module under `site/src`, emitted as an external file |
| Inline event-handler attributes | none in the prototype (`el.onclick = …` is JS-assigned, which is CSP-safe) | none; assignment through the `on*` property or `addEventListener` |
| `<style>` blocks | the prototype has one large block (lines 8–219) | none; Astro stylesheets are external files |
| `build.inlineStylesheets` | **absent from `site/astro.config.mjs`** (Astro's `auto` inlines small sheets; the committed `dist/index.html` carries one `<style>` block) | `'never'` |
| `vite.build.assetsInlineLimit` | `0` | `0`, unchanged |
| Meta policy | none | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` |

`style-src` keeps `'unsafe-inline'` for two reasons: the prototype positions a
few elements with `style="…"` attributes (the bar labels' `right`/`left`, the
ladder root's static size), and Astro's scoped-style attributes are not a
script surface. `style.setProperty` and `el.style.x = …` are CSSOM writes and
are unaffected by CSP, so no script needs `'unsafe-inline'`. The stricter
`style-src 'self'` (no style attributes at all) is possible once the bar labels
are positioned by classes; it is listed as an MS4 option, not a requirement.

The build test that enforces this (in `site/tests/site.test.ts`, extended):
every emitted HTML file contains no `<script>` without `src`, no `on*=` handler
attribute and no `<style` block; `dist` has an external CSS file per page.

## 7. Lite mode

Specified in `docs/site/design-rules.md` §6. Hooks that exist from MS1:

- `site/src/lib/lite.ts`: `lite()` reads `?lite=1`, `navigator.connection.saveData`
  and `navigator.deviceMemory <= 2`, caches the answer, and is the only place
  the test lives.
- `Base.astro` sets `data-lite="on"` on `<html>` before first paint (an inline
  script would violate CSP, so this is done by the first module, with
  `document.documentElement.dataset.lite`; the CSS uses
  `:root[data-lite="on"]` and a class in the first module so the unstyled flash
  is bounded).
- Each ambient component checks `lite()` once at boot and does not create its
  canvas, listener or loop.
- Glass drops `backdrop-filter` but keeps the scrim and the gradient.
- The motion module returns the final state for every effect.

MS4 turns the switch on, measures the bundle delta and adds the Playwright test
`lite mode drops the atmosphere and keeps every fact`.

## 8. Deviations from the prototype

Every change to the prototype's design, with the rule that requires it. Each is
also written next to the component that implements it.

| Prototype | Deviation | Reason |
| --- | --- | --- |
| glass panels paint only the white gradient over the page | an ink scrim at 78 % is painted first | without it muted text over the cool orb and orange both fall below 4.5:1 (brand §3, and the checker's selftest) |
| the pointer specular follows the pointer across the whole panel | the specular is clipped to the panel's top 44 px | at `.16` under text, muted copy falls below 4.5:1 (brand §3) |
| `--ln` is the resting border of every control | `--edge` (paper at 48 %) is the resting border where the control has no other cue | `--ln` is 1.32–1.44:1, below the 3:1 boundary floor (brand §3) |
| `--rose` is the Derived badge and the outer ladder ring | kept, but the mark is also half-filled and labelled | colour is never the only channel (design rule 9) |
| four status hues in the previous palette | deleted; evidence is shape plus word | the prototype never had four hues; the skin follows it |
| `#fx` scroll field and the hero canvases always animate | paused off-screen, absent in lite mode | canvas budget (design rule 14) |
| fonts fetched from Google Fonts | self-hosted variable subsets | no third-party request, CSP `font-src 'self'` (skin-plan §5) |
| wordmark and favicon are inline data URIs | tracked vector assets | cacheable, real alt text, smaller HTML |
| `theme-color` is `#07080A` | `#13161B` | the document ground is the slate, not the ink (brand §1) |
| the footer's claims line says `771 of 771` | rendered from `F-claims-count` (852 of 852) | the prototype's number is stale (fact-gaps §2) |
| the results' two speed-ups are `Extrapolated ≈` | `Derived`, no `≈` | the artifact class is `derived` (fact-gaps §2) |
| the hero and footer taglines | **kept verbatim**: `Post-quantum DNSSEC, measured.` and `Sign once. Prove many.` | the design authority's words; "prove" is read as "demonstrate", and the limits paragraph keeps the formal-verification disclaimer. The earlier audit's suggested replacement is not adopted |
| the page index is a 72-tick rail | kept, but its links are a real list with focus states | the prototype's rail is pointer-only at `1100px` and below; the links must stay reachable |
| the menu button toggles a class | kept, plus `aria-expanded` and focus return | the prototype sets `aria-expanded` but does not return focus |
| the ladder groups are plain buttons | kept, plus arrow-key navigation inside each group | the prototype implements arrows for the tabs but not the ladder (audit §6) |

Deviations that need a design decision rather than a rule are not made here;
they are listed as open questions in the phase record.

## 9. Bundle and budget report

Each phase reports, from the built `site/dist`:

- the HTML, CSS and JS bytes per route, gzipped and brotli, before and after;
- the number of `<script>` tags (external), the number of CSS files, and the
  absence of inline script and style;
- the canvas count in the source (at most five `<canvas>` tags) and the number
  of rAF loops that can run at once (at most four);
- the font bytes against the 80 KiB budget;
- the light/dark `theme-color` (dark only: `#13161B`).

No number in the report is typed: they are read from `du`, `wc -c` and the
build's own manifest.

## 10. What MS0 does not do

- It does not touch `site/`, so the built site still ships palette v2, the old
  hero and four status hues. `cargo xtask site-check` therefore reports the old
  design as clean and the new documents as authoritative; the first component
  change is MS1.
- It does not add a fact, a generator or a claim. `docs/site/fact-gaps.md` is a
  work list.
- It does not enable lite mode; it fixes the hook and the inventory column.
- It does not remove a single line of site source or a single test.
